# Lesson GCal Sync for Kimini

Kimini英会話で予約したレッスンを、Googleカレンダーに自動で登録するChrome拡張機能。
予約をキャンセルすれば、カレンダーからも消える。

> **非公式ツールです。** Glats Inc. および学研グループとは関係ありません。
> 「Kimini」は Glats Inc. のサービス名です。

## できること

- レッスンを予約すると、Googleカレンダーに予定が入る
- 別の環境で予約した分も、ボタンひとつでまとめて取り込める
- 予定には講師名・コース名・教材名と、レッスン詳細ページへのリンクが入る
- 予約をキャンセルすると、カレンダーからも予定が消える
- 同じ予約が重複して登録されることはない

登録される予定の例。

```
Kimini英会話 - Erich
8月29日（土）8:00〜8:25
  コース: ニューストークコース
  教材: ＜Lifestyle＞Simple ways to stay cool in hot weather
  講師: Erich
  レッスンの詳細: https://kimini.online/plus/lesson/318588168
  通知: 10分前
```

## 使いはじめる

Chrome ウェブストアには出していないので、リポジトリを取得して読み込む。

```sh
git clone https://github.com/otokichi3/kimini-plus.git
```

1. Chrome で `chrome://extensions` を開く
2. 右上の「デベロッパーモード」をオンにする
3. 「パッケージ化されていない拡張機能を読み込む」で、clone したフォルダを選ぶ
4. ツールバーの拡張機能アイコンを押し、「Googleアカウントを連携」を押す
   （アイコンが見えないときは、ツールバーのパズルピースから固定しておくと使いやすい）

**Google Cloud の設定は要らない。** OAuth クライアントは同梱の設定を共有している。

連携のときに「このアプリは Google で確認されていません」と表示される。
この拡張機能が Google の審査（OAuth 検証）を受けていないためで、
「詳細」→「安全でないページに移動」で進める。不安なら `src/background.js` を読んでほしい。
カレンダー以外への通信はしていない。

あとは普段どおり Kimini でレッスンを予約すれば、カレンダーに入る。

## 別の環境で予約したとき

この拡張機能は Kimini のページを開いたときに動くため、**別の Chrome プロファイルや
スマートフォンで予約した分は、そのままでは取りこぼす。**

ツールバーの拡張機能アイコンを押すと画面が開く。「予約済みのレッスンを取り込む」を押せば、
まだカレンダーに入っていない予約をまとめて登録できる。キャンセルされた分の削除も同時に行われる。

Kimini のページを裏でタブに開いて確認する仕組みなので、その Chrome プロファイルで
Kimini にログインしている必要がある。

## 設定

ツールバーの拡張機能アイコンから変更できる。

| 項目 | 既定値 | 説明 |
| --- | --- | --- |
| 自動登録 | オン | オフにすると何もしない |
| カレンダーID | `primary` | 別のカレンダーに入れたい場合に指定する |
| タイトル | `Kimini英会話 - {teacher}` | `{teacher}` `{course}` `{material}` が使える |
| 通知 | 10分前 | `-1` にすると通知を設定しない |

## しくみ

Kimini は SPA ではなく通常のページ遷移で動いており、予約は `reserve_f` フォームが
`/plus/lesson/reserve/result` に POST して確定する。kimini.online 自身の XHR は無いため、
API のレスポンスを傍受する方法は取れない。そこで DOM から読み取っている。

- **予約確定の直後**に着地したページから読み取って、その場で登録する
- **取りこぼしの保険**として、学習カレンダーやレッスン一覧を開いたときにも未登録の予約を拾う

レッスン詳細リンク `/plus/lesson/<id>` の id を一意キーとし、カレンダー側の `iCalUID` に使う。
同じ予約を何度読み取っても、登録されるのは1件だけになる。

クラス名は `box` や `shadow` のような汎用的なものばかりでセレクタとしては当てにならないため、
日時の表記 `YYYY-MM-DD (曜) HH:MM-HH:MM` を手がかりにしている。

受講済みのレッスンにはラベルが付かない（予約中は「予約」、不成立は「不成立」）ため、
ラベルだけでは受講済みと予約を区別できない。開始時刻が未来であることを主な条件にしている。

### 手動での取り込み

Kimini のセッション Cookie は、設定ページ（`chrome-extension:` のページ）から直接 `fetch` しても
送られるとは限らない。確実なのは Kimini のページ自体に処理させることなので、レッスン一覧を
`?sync=manual` 付きで裏のタブに開き、いつも動いている content script に任せて閉じている。

`?sync=manual` が付いたタブでは、未認証のときに Google のログイン画面を出す。
手動で押したときだけは、黙って失敗するより画面が出たほうがいい。

タブの開閉と結果の受け取りは service worker 側に置いている。ポップアップは閉じると
動作が止まるため、そちらでタブを開くと、閉じられたときに裏のタブが残ってしまう。
いまはポップアップを閉じても取り込みは最後まで走り、結果を受け取れないだけになる。

### キャンセルの検知

キャンセルを拾うには「今どれが予約中か」の完全な一覧が要る。表示中のページはその一部しか
映していないことがあるため、レッスン一覧の検索フォームと同じ POST（`status=reserved`）を投げて
予約中だけの一覧を取り直し、「全Nレッスン」の件数表示と取得件数を突き合わせる。
数が合わないときは、ページ送りの向こうに予約が隠れているとみなして削除を見送る。
見えなかっただけの予約を消してしまわないため。

開始時刻を過ぎたレッスンは削除の対象外にしている。受講を終えたレッスンも「予約中」では
なくなるため、時刻で線を引かないと受け終わったレッスンの予定まで消えてしまう。

削除するのは、この拡張機能が登録した予定だけ。手で作った予定には触らない。

## 動作を確認した範囲

- ニューストークコース、スタンダードPlusプラン、PC の Chrome
- 過去12件のレッスンが並ぶ一覧ページで、未来の予約だけを取り出すこと
- 同じ予約を何度読み取っても重複登録されないこと

他のコースでは教材名の示し方が違う可能性がある。取得できなかった項目は空欄になるだけで、
予定の登録自体は成功する。うまく動かないコースがあれば issue で教えてほしい。

## 構成

```
manifest.json      拡張機能の定義。OAuth クライアント ID もここにある
src/content.js     Kimini のページから予約を読み取る
src/background.js  Google カレンダーに登録・削除する
src/popup.html     ツールバーから開く画面
src/popup.js
```

## 開発者向けのメモ

`manifest.json` の `key` は拡張機能 ID を固定するためのもの。OAuth クライアントは
拡張機能 ID に紐づくため、これが無いと読み込むたびに ID が変わって認証が通らなくなる。
clone した人全員が同じ ID `nngimhenmgcebojjiolkmpgehgpndnpf` になるので、
各自で Google Cloud の設定をしなくても済む。

Google Cloud 側（プロジェクト `otokichi-app`）には次を設定してある。

- Google Calendar API を有効化
- OAuth 同意画面: 外部・本番環境
- スコープ: `https://www.googleapis.com/auth/calendar.events`
- OAuth クライアント: 種類「Chrome 拡張機能」、アイテム ID は上記の拡張機能 ID

未検証アプリのユーザー数上限は累計100人。それを超えて配りたくなったら OAuth 検証が要る。

秘密鍵 `key.pem` は `../kimini-plus-keys/` に置いてある。拡張機能ディレクトリに入れておくと
Chrome が「鍵ファイルが含まれていますが、おそらくその必要性はありません」と警告するため。
開発者モードでの読み込みには不要で、`.crx` にパッケージ化して署名するときにしか使わない。

捨ててはいけない。拡張機能 ID は公開鍵から決まるので、鍵を失うと同じ ID で `.crx` を
作り直せなくなり、OAuth クライアント（アイテム ID に拡張機能 ID を登録している）も
作り直しになる。
